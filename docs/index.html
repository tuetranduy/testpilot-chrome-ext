A better starting point for QA

Manual testing is thoughtful work. The setup around it should not be.

QA teams already know how to find the edge cases that matter. The drag is everything around that judgment: cataloguing fields, translating acceptance criteria, inventing safe test data, and keeping yesterday's results close enough to be useful.

TestPilot is a Chrome extension built to shorten that distance. It works beside the live page, so your test surface and your test notes stay in the same place.

01

From live UI to testable plan

01 / SCAN

See the page like a tester.

TestPilot inspects the current tab's interactive elements, including inputs, selects, buttons, and links. It also captures a screenshot to give the model visual context.

02 / GENERATE

Turn requirements into cases.

Paste or upload acceptance criteria, then generate manual test cases as plain steps or Gherkin. The output is a starting point for a human tester, not a black box.

“The goal is not to replace the tester. It is to give the tester a sharper first draft.”

AI is useful when it handles the blank page and stays open to correction. That is the role TestPilot is designed for: gather the raw material, suggest coverage, and leave the final call with the person who understands the product.

Generated cases can be reviewed and exported to Markdown or CSV. When you return to a site, local history helps you pick up where you left off instead of rebuilding context from scratch.

02

Built for control, not surprise

⌁

Your keys stay yours.

Choose OpenAI, Gemini, Anthropic, or a local OpenAI-compatible model such as Ollama or LM Studio. API keys are stored in chrome.storage.local and are never synced.

⌖

Access is per site.

TestPilot requests host access only when you scan a site for the first time. There is no broad all-sites permission upfront.

↗

Results remain portable.

Keep the workflow lightweight. Review the generated cases, then export them as Markdown or CSV for the tools your team already uses.
