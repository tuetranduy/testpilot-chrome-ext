A better starting point for QA

Manual testing is thoughtful work. The setup around it should not be.

QA teams already know how to find the edge cases that matter. The drag is everything around that judgment: cataloguing fields, translating acceptance criteria, inventing safe test data, and keeping yesterday's results close enough to be useful.

TestPilot is a Chrome extension built to shorten that distance. It works from the live implementation or a Figma Design, so QA can begin before or after the UI reaches the browser.

“The goal is not to replace the tester. It is to give the tester a sharper first draft.”

AI is useful when it handles the blank page and stays open to correction. That is the role TestPilot is designed for: gather the raw material, suggest coverage, and leave the final call with the person who understands the product.

Image and full-page context requires a vision-capable model. Generated cases can be reviewed and exported to Markdown, CSV, or one combined Gherkin .feature file. Source-aware local history keeps web, image, and Figma runs ready to revisit.

02

Built for control, not surprise

⌁

Your credentials stay local.

AI provider keys and the raw Figma personal access token are stored in chrome.storage.local and never synced. Credential fields mask only their on-screen presentation. Replace the Figma token in Settings if it expires.

⌖

Access is exact and timely.

TestPilot requests only the current web origin, Figma API, returned preview origin, or AI provider origin when that connection is needed.

↗

Results remain portable.

Review generated cases, then export Markdown, CSV, or a combined UTF-8 .feature file for the tools your team already uses.
